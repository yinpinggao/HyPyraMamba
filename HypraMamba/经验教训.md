# HyPyraMamba QUH 实验经验教训

## 当前结论

到目前为止，最稳的配置仍然是：

- 结果目录：`RUNS_QUH_100_30_WEIGHTED_ACCUM_GROUP2`
- 模型名：`MambaHSI_competitive_diff_alpha0p5`
- 数据协议：QUH `100 train / 30 val / rest test`，固定 `splits/quh_100_30_seed0-9`
- 训练方式：`tile_size=512`，`tile_overlap=32`，`tile_update_groups=2`
- 优化配置：`Adam`，`lr=0.0003`，`weight_decay=1e-5`，`scheduler=none`
- 损失配置：`label_smoothing=0.05`，`class_weight_mode=balanced`
- 模型配置：`hidden_dim=128`，`token_num=4`，`pool_size=2`，`high_res_skip=none`，`prca_num_scales=3`，`prca_num_layers=2`
- 预处理：`Gaussian sigma=1.0 -> PCA 30 -> ImageStretching(2,98)`，不做 PCA whiten

三数据集结果：

| 实验 | QUH-Pingan OA | QUH-Qingyun OA | QUH-Tangdaowan OA | 结论 |
| --- | ---: | ---: | ---: | --- |
| `WEIGHTED_ACCUM_GROUP2` | 94.97 | 90.70 | 95.92 | 当前主基线 |
| `CORELOSS_GC_PRCA_S3L2` | 95.15 | 90.96 | 95.92 | 精度略有波动，但训练明显变慢 |
| `HS4M_CORELOSS_GC_PRCA_S3L2` | 94.64 | 90.20 | 96.13 | 速度提升，但精度不稳 |
| `PCAW_TOKEN8_CORELOSS_GC_PRCA_S3L2` | 94.92 | 90.50 | 96.29 | Tangdaowan 略涨，Pingan/Qingyun 不稳且更慢 |

因此，后续改动不能再默认认为“更像 HS4M”或“更细 token”就会更好。当前证据只支持保留 `WEIGHTED_ACCUM_GROUP2` 作为默认配置。

## 失败尝试 1：core-only tile loss + grad clip

动机：

- overlap tile 训练时，重复区域会被多个 tile 参与 loss。
- 只在每个 tile 的唯一 core 区域算 loss，理论上更干净。
- 加 `grad_clip_norm=1.0`，希望提高稳定性。

结果：

- Pingan：`94.97 -> 95.15`，有小幅提升。
- Qingyun：`90.70 -> 90.96`，有小幅提升。
- Tangdaowan：`95.92 -> 95.92`，基本持平。
- 训练时间显著增加：
  - Pingan：`2312s -> 4725s`
  - Qingyun：`1324s -> 2712s`
  - Tangdaowan：`1784s -> 3545s`

教训：

- 这个改动不是纯收益。精度收益很小，训练时间代价很大。
- 对当前模型来说，原来的整 tile loss 加标注像素加权已经足够有效。
- 不应该为了理论上更干净的 loss，牺牲接近 2 倍训练时间。

## 失败尝试 2：HS4M-style high-res shallow fusion

动机：

- HS4M 使用 `deepest_up + stem_out + stage1_fused` 的高分辨率融合。
- 我们尝试新增 `high_res_skip=hs4m`，让 heavy Mamba/PRCA 在低分辨率上跑，再上采样和浅层特征融合。

结果：

- Pingan：`94.97 -> 94.64`，下降。
- Qingyun：`90.70 -> 90.20`，下降。
- Tangdaowan：`95.92 -> 96.13`，小幅上升。
- 速度确实提升，但三数据集精度不稳定。

教训：

- 只学 HS4M 的“浅层相加”是不够的。
- HS4M 真正的有效部分包括多 stage 层级结构、Spa/Spe VSSM、EDFFN、stage1/deepest 融合和训练 recipe。
- 直接加一个 high-res skip，容易改变特征分布，但没有提供足够的深层 refinement。
- 这个方向如果继续做，应该是完整结构消融，而不是再加一个浅层 shortcut。

## 失败尝试 3：PCA whiten + token_num=8

动机：

- HS4M 统一使用 PCA whiten。
- MambaHSI 的 spectral scan 默认思路更接近 `token_num=8`。
- 这是低成本尝试，不直接改模型主体。

结果：

- Pingan：`94.97 -> 94.92`，略降。
- Qingyun：`90.70 -> 90.50`，下降。
- Tangdaowan：`95.92 -> 96.29`，上升。
- 训练时间变长：
  - Pingan：`2312s -> 3617s`
  - Qingyun：`1324s -> 1889s`
  - Tangdaowan：`1784s -> 2508s`

教训：

- `whiten + token_num=8` 不是稳定收益。
- Tangdaowan 的提升不能代表三数据集整体提升。
- token 更细会改变 spectral branch 的建模粒度，但不一定适合所有 QUH 子集。
- 以后不能只看一个数据集涨了就合并默认配置。

## 失败尝试 4：照搬 HS4M recipe 的冲动

动机：

- HS4M 使用 `AdamW + lr=0.001 + weight_decay=1e-4 + cosine + 100 epoch + whiten`。
- 它在 QUH 上结果强，因此看起来值得迁移。

实际问题：

- HS4M 的 recipe 是和它自己的结构绑定的。
- 当前模型的最佳记录来自 `Adam lr=0.0003 + scheduler none + 200 epoch + balanced class weight + label smoothing 0.05`。
- 直接改 recipe 会同时改变优化器、学习率、weight decay、scheduler、epoch 数、class weight、label smoothing、whiten，变量太多。

教训：

- 训练 recipe 不能整包迁移。
- 如果要试，必须一次只动一两个变量，例如只试 `AdamW`，或只试 `cosine`，不能把一整套 recipe 混在一起。
- 没有完整三数据集结果之前，不能把它写成默认配置。

## 总体教训

1. 默认配置必须由三数据集共同决定，不能由单数据集提升决定。

2. 速度提升和精度提升要分开评价。`high_res_skip=hs4m` 提速明显，但精度不稳定，所以不能作为主线。

3. “更像强 baseline”不等于更好。HS4M 的优势来自完整结构组合，不是某一个开关。

4. 小样本固定 split 下，训练配置非常敏感。`class_weight_mode=balanced` 和 `label_smoothing=0.05` 目前仍然是有效组合，不应轻易去掉。

5. 改动必须先和当前代码路径对齐。比如默认 `high_res_skip=none` 时，`pool_size=2` 是在 Mamba/PRCA 之后发生的，不能误以为它已经降低了 heavy block 的计算量。

6. 实验命名要明确写出关键变量。否则后面无法判断到底是 core loss、whiten、token、skip、scheduler 还是 PRCA 层数导致变化。

7. 每次只改一个主变量。之前一些实验同时改变 loss、validation、grad clip、whiten、token 或结构，导致结果不好解释。

8. 不要因为参数量小就低估运行代价。整图 tile 输入下，空间 Mamba/PRCA 的代价主要来自 `H*W` 序列长度和 tile 数，不是单纯参数量。

## 后续建议

短期内不要继续改默认模型结构。当前默认应固定为 `RUNS_QUH_100_30_WEIGHTED_ACCUM_GROUP2` 这套配置。

如果后面继续实验，优先顺序应该是：

1. 先保留 GROUP2 全部配置，只单独试一个训练变量。
2. 每个实验必须三数据集都跑完 10 seed。
3. 同时记录 OA、AA、Kappa、mIoU、训练时间。
4. 只有三数据集平均收益明确、且训练时间代价可接受，才允许合并成默认配置。

当前最重要的结论是：先不要再把多个“看起来合理”的 trick 叠加到一起。主线应该回到 `WEIGHTED_ACCUM_GROUP2`，后续每一步都做严格消融。

## 2026-07-10 验证集筛选修正

1. 超参搜索不再运行 test。筛选阶段必须使用 `--evaluate_test false`，只读取 `mean_validation_result.txt`。只有候选配置根据验证集锁定后，才能打开 test 做最终 10-seed 报告。

2. 旧代码用 `checkpoint_score >= best_val_score` 保存，会把并列最优的更早 checkpoint 反复覆盖成最后一个 epoch。Qingyun 验证 OA 高度量化，某些 seed 有数十个并列 epoch。新规则为 `--checkpoint_tie_break secondary`：Qingyun 按 `(OA, mIoU, 更早 epoch)`，Tangdaowan 按 `(mIoU, OA, 更早 epoch)`。

3. 同一批消融中，去掉 spectral branch 后 Qingyun 从 `90.93/78.22` 提高到 `91.41/79.32`，Tangdaowan 从 `95.79/87.83` 提高到 `96.11/89.47`（OA/mIoU）。这说明 spectral branch 对这两个数据集的融合强度可能偏大，但不能直接删分支。首轮只筛选 `spectral_fusion_scale=1.0/0.75/0.5/0.25`，保留双分支与 competitive fusion。

4. `scipy.ndimage.gaussian_filter(data, sigma=1.0)` 会同时平滑 H、W 和光谱轴，而 spectral branch 显式使用相邻谱差。已增加 `gaussian_spectral_sigma`。它是第二轮独立变量，先试 `0.0`，不得与 fusion scale 在首轮同时改。

5. QUH 固定 split 每类都是 100 train / 30 val。因此 `balanced` 基础权重全为 `1.0`，与 `none` 等价；OA 与 AA 在验证集上也等价。后续不再浪费资源比较 `balanced/none` 或 `OA/AA/Kappa` checkpoint。
